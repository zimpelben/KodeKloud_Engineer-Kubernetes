There is a production deployment planned for next week. The Nautilus DevOps team wants to test the deployment update and rollback on Dev environment first so that they can identify the risks in advance. Below you can find more details about the plan they want to execute.  

1. Create a namespace `devops`. Create a deployment called `httpd-deploy` under this new namespace, It should have one container called `httpd`, use `httpd:2.4.25` image and `4` replicas. The deployment should use `RollingUpdate` strategy with `maxSurge=1`, and `maxUnavailable=2`. Also create a `NodePort` type service named `httpd-service` and expose the deployment on `nodePort: 30008`.  

2. Now upgrade the deployment to version `httpd:2.4.43` using a rolling update.  

3. Finally, once all pods are updated undo the recent update and roll back to the previous/original version.  

`Note:`

a. The `kubectl` utility on the `jump-host` has been configured to work with the Kubernetes cluster.  
  
b. Please make sure you only use the specified image(s) for this deployment and as per the sequence mentioned in the task description. If you mistakenly use a wrong image and fix it later, that will also distort the revision history which can eventually fail this task.

### Answer

1. Create the namespace `devops`

```
kubectl create namespace devops
```

2. Create the httpd deployment manifest.

```
apiVersion: apps/v1
kind: Deployment
metadata:
  name: httpd-deploy
  namespace: devops
  labels:
    app: httpd
spec:
  replicas: 4
  selector:
    matchLabels:
      app: httpd
  template:
    metadata:
      labels:
        app: httpd
    spec:
      containers:
      - name: httpd
        image: httpd:2.4.25
        ports:
        - containerPort: 80
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 2
```

3. Create a service manigest.

```
apiVersion: v1
kind: Service
metadata:
  name: httpd-service
  namespace: devops
spec:
  type: NodePort
  selector:
    app: nginx
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30008
```

3. Apply the service and deployment manifest.

```
# create deployment
kubectl apply -f httpd-deploy.yaml

# create service
kubectl apply -f httpd-service.yaml
```

4. Check if the deployment has successfully been created.

```
kubectl describe deployments.apps -n devops
```

4. Update the container image.

```
kubectl set image -n devops deployments/httpd-deploy httpd=httpd:2.4.43
```

5. Check rollout status.

```
kubectl rollout status -n devops deployment httpd-deploy 

# output if successful
deployment "httpd-deploy" successfully rolled out
```

6. We can also check with the `describe` command to verify rollout as this will tell us the exact image.
7. Undo the rollout.

```
k rollout undo -n devops deployment httpd-deploy 
```

8. Check if the image is back to the original using the `describe` command.

```
kubectl describe -n devops deployments.apps
```

9. Click check to complete the task.
