Last week, the Nautilus DevOps team deployed a redis app on Kubernetes cluster, which was working fine so far. This morning one of the team members was making some changes in this existing setup, but he made some mistakes and the app went down. We need to fix this as soon as possible. Please take a look.  

The deployment name is `redis-deployment`. The pods are not in running state right now, so please look into the issue and fix the same.  
  
`Note:` The `kubectl` utility on the `jump-host` has been configured to work with the Kubernetes cluster.

### Answer.

1. Check the logs of the deployment.

```

kubectl logs deployments/redis-deployment 

# Output
Error from server (BadRequest): container "redis-container" in pod "redis-deployment-795ffcb56c-pb2qf" is waiting to start: ContainerCreating
```

2. The logs indicate that there is an issue in the Container creating. 
3.  To get more information we can use the describe command on the deployment.

```
kubectl describe redis-deployment
```

4. Lets focus on the container information.

```
  redis-container:
    Image:      redis:alpin
    Port:       6379/TCP
    Host Port:  0/TCP
    Requests:
      cpu:        300m
    Environment:  <none>
    Mounts:
      /redis-master from config (rw)
      /redis-master-data from data (rw)
```

5. The image is the issue as there is a typo; it should be `redis:alpine`.
6.  Lets set a new image to correct the type.

```
kubectl set image deployments/redis-deployment redis-container=redis:alpine
```

7. Check rollout status.

```
# Output
Error from server (BadRequest): container "redis-container" in pod "redis-deployment-795ffcb56c-pb2qf" is waiting to start: ContainerCreating

# output if some time has passed
error: deployment "redis-deployment" exceeded its progress deadline
```

8. Although the image has been corrected, the container is either not creating or is exceeding the progress deadline.
9. Lets check the pod and see if there is any further information there.

```
kubectl describe pods redis-deployment-5d849ccf9d-n2lmj 
```

10. When we check the events section of the pod, we see there is an issue with mounting a config to the container.

```
Events:
  Type     Reason       Age                 From               Message
  ----     ------       ----                ----               -------
  Normal   Scheduled    10m                 default-scheduler  Successfully assigned default/redis-deployment-5d849ccf9d-n2lmj to jump-host
  Warning  FailedMount  16s (x13 over 10m)  kubelet            MountVolume.SetUp failed for volume "config" : configmap "redis-cofig" not found
```

11. It appears a configmap is being used but the name appears to be misspelled `redis-cofig`.
12. We can check the name of the configmap using;

```
kubectl get configmaps

#output
NAME               DATA   AGE
kube-root-ca.crt   1      64m
redis-config       2      21m
```

13. In order to fix the configmap name, we create a yaml file from the current deployment by exporting the output to yaml as such.

```
kubectl get deployments.apps redis-deployment -o yaml > redis-deployment.yaml
```

14. Now we can edit the file and changing the name of the configmap under the volumes section.

```
# old setup
      volumes:
      - emptyDir: {}
        name: data
      - configMap:
          defaultMode: 420
          name: redis-cofig # misspelled name
        name: config
        
# new setup
      volumes:
      - emptyDir: {}
        name: data
      - configMap:
          defaultMode: 420
          name: redis-config # spelling corrected
        name: config
```

15. Save and exit the file.
16. Lets the delete the current deployment before apply the new manifest.

```
# delete current deployment
kubectl delete -f redis-deployment.yaml

# create new deployment
kubectl apply -f redis-deployment.yaml
```

17. Will do a final check to see if the pods are now running.

```
kubectl get pods

# output
NAME                                READY   STATUS    RESTARTS   AGE
redis-deployment-5476b4ddd6-zsbwq   1/1     Running   0          12s
```

18. The deployment is now up and running and we can click check to complete the task.
